# Reviewed source identity

Migration0009 adds source-pair cases, typed source decisions, current relations and a graph revision. It extends0002–0008 without changing them. These are internal storage primitives; no phone feature, authenticated HTTP endpoint or confidence badge is delivered here.

`v2_open_source_case(actor,a,b)` returns the single case for the ordered pair. Both immutable, privately owned source records are the evidence under review. `v2_review_sources` requires a live reviewer/administrator, expected case and graph revisions, a request UUID, explicit classification and a reason. The future authenticated backend must derive actor from the session and show both records to the reviewer; SQL cannot prove that a human inspected them. No role grants occur in this migration.

Only `same_origin` edges form components. `suspected_same_origin` remains visible for review but never merges origins. `separate` removes that pair's edge. Reversal names the current decision and removes its effect; it does not resurrect an older confirmation. A subsequent review can establish a new edge. Reversing one edge does not break a component if another independently reviewed path still connects it. Explicit split work must address all relevant edges.

History uses the real `source` decision subtype, case lineage and immutable source IDs until erasure. Pair ordering prevents duplicate reverse pairs and self-links. Exact request retries return the original receipt without reapplying it; changed payload or erased evidence conflicts. Case and global graph revisions reject stale context. Shared transport serialization preserves conflicts at READ COMMITTED and REPEATABLE READ; account locks precede it.

`v2_source_footprint(observation)` returns the graph revision, original citation IDs, a distinct set of current group representatives and `known`. Representatives are the smallest current source UUID in each component, not permanent public identifiers. Consumers must use the returned version and subject input generation; deleting a representative can change that ID. The decision stream versions reviewed edges; erasure intentionally prevents reconstruction of removed private identities.

An observation citing A and B has two groups unless an explicit reviewed path connects them. Citations never create identity edges. Equal fingerprints, dates, locators, authors or text do not establish shared origin. No URLs are fetched. A footprint is unknown for missing citations, inactive observations, or any cited hearsay/unprovided/import source. This helper does **not** establish current dates, complete scope, contributor independence or corroboration. Those remain full assessment-policy work, including the one-account ceiling and disjoint witness-pair selection.

Adding a citation changes the inputs and invalidates affected decisions. Existing citations cannot be silently rewritten or removed: use an appended corrected observation and its existing supersession history. Parent source/observation erasure is the exception. Source text/ownership remains immutable; another account cannot cite someone's private source record directly. Instead, review can relate their separately owned copies.

Changes collect the whole old component before a split, invalidate dependent field and association decisions (including descendants), obsolete affected candidates, clear selected projections, advance affected original/effective/historical-target subject generations and enqueue recomputation. Adding a citation or changing a relation advances the graph revision. Reversal never reinstates old derived decisions. Existing state/target triggers continue to handle withdrawal and moderation.

Source/account erasure removes private source rows and citations, clears both pair identifiers from affected case tombstones, redacts source-case/component notes and transport-review cases quoting affected observations, erases copied field values and subject snapshots, and queues recomputation synchronously. Other independently supported edges can survive. Deleting only a reviewer anonymizes actor and notes while preserving source evidence independently owned by others. No private locator is copied into jobs or public projections. Erasure conservatively invalidates more than a minimal field where dependency separation is unavailable.

New tables have RLS and backend SELECT only. Mobile/PUBLIC access is revoked even under permissive hosted defaults. Only constrained review and read functions are backend callable; mutation helpers remain owner-only. Existing source/citation tables retain their established backend access, with ownership, immutability and invalidation triggers. No automatic candidate generator, public source viewer, cross-target reviewer UI, task projection or full support/freshness engine is claimed. Complete those and canonical-writer integration before exposing v2.

Tests run against a disposable PostgreSQL17 database: populated0008 upgrade, all query mappings, graph/citation semantics, reviewed reversals, request retries, privileges, erasure, selected-decision invalidation and two-connection review/erasure races. CI evidence belongs in the project validation manifest; this document alone does not assert a passed run.
