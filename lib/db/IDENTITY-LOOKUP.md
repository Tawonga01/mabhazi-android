# Reviewed operator aliases and namespaced external IDs

Migration0026 adds private proof-bound identity lookup. `v2_lookup_operator_alias(name)` uses the existing case/whitespace search key, retains punctuation and returns unresolved, resolved or ambiguous. Ordinary display-name equality does not establish an alias. Distinct reviewed companies stay distinct even with the same spelling; the response includes at most50IDs and an explicit more flag, never a falsely unique result. Original reports and canonical display names are preserved. The lead consumer adds alias hints to corridor explanations only; it does not assign a name-only report to a scheduled run or create an identity link.

`v2_register_import_revision` requires administrator authority and an exact previous namespace epoch. Namespace, entity kind, external ID and import version are opaque/case-sensitive; versions are not sorted as strings. Same request retries return the original receipt without reviving an old version. `v2_lookup_external_id(namespace,kind,id,version)` resolves only an active mapping with its exact current reviewed origin and registered revision. Owner-loaded legacy rows require review. Remapping proposes the prior active mapping ID and must be reviewed before appending a new mapping and retiring the old one; a stale head, namespace revision or subject epoch aborts.

`v2_propose_identity_binding` captures source/target epochs, declared observation revisions and desired alias or mapping context. Alias proof is one original operator-name observation. Mapping context is an explicit administrator declaration supported by one to100 active observations from the original source. `v2_review_identity_binding` and `v2_apply_identity_binding` reuse reviewer roles/cases/decisions and validate the exact declared evidence. Mapping proposal/review/apply requires an administrator; aliases accept reviewer or administrator authority. Each new review case has a fixed context: rejection or needs_context requires a fresh proposal rather than silently reusing stale epochs. Source/target changes, review reversal, import retirement and proof withdrawal invalidate lookup. Later reads check the same fences even before deferred projections are refreshed. Erasure removes copied names and request fingerprints; value-free event history remains. Reversal deactivates the current effect and does not revive an older mapping.

Six new tables have RLS and backendSELECTonly; hosted anon/authenticated users get no direct access. Only the two read-only lookup functions are granted to mabhazi_api. Proposal/review/apply/reversal/import-authority helpers remain owner-only until authenticated APIs bind the caller to an authorised account. No reviewer-role bootstrap, public endpoints, importer feed, canonical creation, observation reassignment, confidence or publication is supplied by this layer. These remain WP05/WP07 and the full R01–R14 scope. A reviewed alias is a name-to-company binding, not proof of affiliation or a route timetable.

The existing fenced association consumer and catalog epochs provide bounded durable wakeups for alias changes. Alias-derived candidate fingerprints are invalidated, and erased proof clears both copied hashes. SQL patching verifies the exact prior body, SECURITYDEFINER and pinned search_path, normalising only CRLF representation. The selected source mirror is not a full clone or independent build: canonical/fresh/repeat/populated/browser-format SQL and real behaviour are verified by GitHub CI before any preview application.

The reviewed-evidence erasure callback also handles a statement deleting both the original reporter and review actor: an actor already absent in that statement is cleared before evidence redaction rechecks its FK. Existing actor-erasure flags/private-note removal and value-free audit history are retained. Both ordinary backend-role account erasure and this two-account case are covered; no account deletion is performed in a live service by these tests.
