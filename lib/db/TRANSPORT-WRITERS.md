# Reviewed transport writers — transport-writers/1

Migration0015 adds an immutable proposal → explicit review → application history for four observation-backed structural edits: a route's operator identity, named/approximate stop location, a run's scheduled departure/arrival, and a pattern's ordered resolved stop list. It uses the existing reviewer role and a dedicated identity case bound permanently to the proposal. The proposal contains the exact before/after transport snapshot, observation scope and observation/target revision. A reviewer must inspect that proposal and approve its exact evidence. Human interpretation adds no witness and does not grant timetable publication.

`v2_propose_transport_edit(actor,subject,expectedRevision,observation,requestId)`, `v2_review_transport_edit(actor,edit,expectedCase,expectedSubject,action,reason,note,requestId,reverseId)` and `v2_apply_transport_edit(actor,edit,review,requestId)` remain owner-only until the authenticated API binds the actor. Proposers use the existing reviewer capability; public users still submit ordinary observations without a reputation prerequisite. A delayed approval or application cannot overwrite newer input or structure. Receipts return the original result and never restore invalidated effects. A different input with the same request ID conflicts. The scoped review helper completes and immediately checks the decision registry even when the caller uses immediate constraints, and keeps an exact review retry receipt. Proposal case bindings, before/after values and event history are immutable apart from mandated erasure.

Time writers accept scheduled observations only. Date-specific evidence cannot redefine an unbounded recurring run; existing run validity must fit the observation date/effective period. Declared timezone/calendar must match its plan. Unknown parent calendar/timezone remains unknown. Actual departures cannot become recurring schedules. Stop coordinates retain their declared precision and cannot silently round; surveyed precision needs a separate future evidence workflow.

Pattern changes require resolved stop IDs, explicit ordered permissions and explicit completeness. Named-only places require later reviewed place resolution. Application creates/seals a new version with an edit/review origin; existing plans/runs retain their versions. Reversal can select the old sealed version, never rewrite either list. Draft version number races and integrity failures roll back the entire edit/history/job transaction.

Application runs existing0014 dependency propagation and records final revisions/generations for that operation. Later parent/child edits invalidate the current edit head synchronously. Reversing its review restores the before snapshot only while that edit remains current and the projection still matches its approved after snapshot. If it was superseded or invalidated, reversal is historical and cannot overwrite newer structure or revive an earlier approval. Read results identify the exact edited field and scope. The reviewed status covers that edit only; unchanged fields in the structural snapshot do not acquire review, freshness or confidence. Results distinguish reviewed, stale, retired and unreviewed; stale/unsupported projections return no snapshot. Raw transport tables remain internal draft structures. The read is a review-validity boundary, not the future full confidence/calendar/publication gate.

Withdrawal/hiding/supersession or changed observation assignment invalidates its current edit and dependent projections. Losing materialisation authority keeps a newly reviewed target association intact; it does not treat an evidence move as a new structural identity edit. Deleted supporting evidence may have been copied into later before/after snapshots, so erasure conservatively redacts all edit snapshots for that subject, preserving independently owned observations for fresh review. Erased receipts remain redacted tombstones. Reviewer/proposer account deletion clears actor identity and retry fingerprints while retaining independently owned transport evidence. Private notes/source locators are never copied into these snapshots; all four new tables are backend SELECT-only with RLS and no app-client grants. No email is introduced.

Compound review/reversal actions can advance revisions again after the event's operation boundary. APIs must read final current values in the same transaction instead of caching event revisions. Review UI must display this dedicated proposal alongside its evidence; an ordinary field/candidate case cannot substitute for its approval.

Remaining work: initial contribution/origin capture and controlled creation of resolved subjects; service-plan/calendar/windows/run-stop-time writers; surveyed precision; reviewed actual/legacy/external mappings and operator aliases; cross-target observation materialisation; complete canonical/publication validation; role/lease-bound APIs and workers; reviewer/mobile screens; live inventory/backfill/restore, performance testing and signed delivery. Existing structural fixture privileges do not establish production writer authority. This chunk does not close WP02 or R01–R14.
