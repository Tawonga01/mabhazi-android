# Affiliation and source issuers

Migration 0012 adds a separate account/operator claim, dated private proof and administrator review. It does not create a global verified-company badge. The earlier operator aggregate remains unverified; callers use the current relationship read. A route observation naming a company, email domain, or company name cannot establish affiliation.

Owner-only primitives: `v2_claim_affiliation`, `v2_add_affiliation_proof`, `v2_review_affiliation`, `v2_erase_affiliation_proof`, and `v2_record_source_issuer`. The future authenticated API must bind actors to verified accounts; no new writer grant or live role is added. Review requires an active administrator other than the claimant, exact case/operator revisions, explicit private proof IDs, reason and retry key. A claim may be rejected, request context, be verified, revoked or reversed. Reversal leaves it pending; it never revives an older approval. Proof is dedicated authorization documentation or an independently checked confirmation, not a transport observation. The administrator must actually inspect it; SQL enforces bindings, not real-world authenticity.

Proof has an explicit observation instant and deadline no later than 180 days afterward (the existing affiliation recheck policy). Review cannot outlive any included proof. Owner-only historical-clock helpers support deterministic verification; backend current-time reads gate expiry even when processing sleeps. Verification and issuer linkage queue recheck work. No independent runner is implemented by this migration.

Source issuer assertions belong to the source owner and support only document/operator-statement sources. Immutable events retain corrections and withdrawal, with a protected current pointer. An optional affiliation reference must currently cover that exact owner and named operator. Public summaries say `issuer_claimed` or `affiliated_submitter`; the latter describes the submitting account, not document authenticity or route truth. A renewed affiliation requires an explicit new source event to use it. Same issuer alone never merges sources or supplies another witness. Existing source invalidation propagates issuer/review changes to assessments and selected fields without changing the confidence policy.

Claim/proof/review/issuer request fingerprints bind exact content and revisions. Exact retries return receipts without reapplying revoked/withdrawn effects. Proof removal keeps an erased receipt tombstone, so replay cannot recreate deleted private material. Claimant deletion clears the account/claimed role, dedicated proof, copied retry fingerprints and source event identities. Proof removal invalidates and redacts the quoting review case and issuer binding. Reviewer-only deletion removes actor/private rationale and retry fingerprints while preserving independently owned proof. Source erasure clears its issuer event identities without erasing independent affiliation proof. Earlier public company identities and nonpersonal audit tombstones can remain; private references never enter public summaries or jobs.

Six new tables have RLS and backend SELECT only; mobile/PUBLIC access is revoked. Histories and exact proof bindings are immutable except required erasure. No current phone behavior, canonical transport publication, administrator interface, file-upload service or email flow changes. Proof storage currently holds private references; any later file store must implement matching authorization and physical-object deletion before accepting real uploads.

Remaining: authenticated actor/private-evidence access and usable review UI; prompt/task storage; complete canonical writer/history/provenance and backfill/recovery; worker leases/independent runner; mobile forms/displays; field and signed device acceptance. Exact validation belongs in the saved manifest, not in this contract.
