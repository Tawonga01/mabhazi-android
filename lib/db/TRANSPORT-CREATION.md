# Controlled identity creation - transport-creation/1

Migration0018 adds explicit creation proposals, review/application event receipts, immutable initial origins and current authority heads. The first two paths create an operator from a named operator.reported observation, or a stop from named boarding.pickup/alighting.dropoff. Selected existing IDs cannot be cloned; arbitrary desired patches are unavailable. Route/pattern/plan/run/actual creation and source alias resolution remain later work.

`v2_propose_transport_creation(actor,source,expectedSourceRevision,observation,kind,requestId)` reserves a UUID in the private proposal, not a registered phantom subject. The dedicated identity case stays anchored to the actual original report. Proposal source snapshot, desired typed projection, exact live observation/assignment revisions and generation are bound immutably. No lead header, observation target or accepted association is rewritten. Same spellings from distinct reports remain separate identities unless later identity review relates them; one evidence item cannot repeatedly materialize another identity of that kind.

`v2_review_transport_creation(actor,creation,expectedCase,expectedSource,action,reason,note,requestId,reverseId)` handles accept/reject/needs_context/reverse with active reviewer authority. Its scoped registry assembly also supports immediate constraints. Review records the actual final source revision/generation after nested invalidation; approval contributes no witness. `v2_apply_transport_creation(actor,creation,review,requestId)` requires that exact current scoped approval, unchanged source projection/epoch and live evidence, then registers the reserved subject/subtype, immutable revision1/generation1 origin, current head and pending assessment work atomically. Only initial subject-subtype assembly is deferred then checked. Caller commit is required before success is acknowledged.

An operator starts unverified with unknown country; a named place has declared city/name, named precision and unknown coordinates/parent. Instructions stay in the observation, not a fabricated stop column. No automatic timetable, route, affiliation, association, corroboration, freshness or publication follows creation. Private proposals/history stay backend SELECT-only, all new mutations owner-only until HTTP actor/role binding. No client writer grants or app emails.

Every proposal/review/apply request has a bounded exact fingerprint/receipt. Same requests return history without repeating effects; changed requests conflict. Applying twice or materializing the same evidence/kind under a fresh request cannot clone identities. Reversal removes origin authority and invalidates downstream interpretations/tasks while preserving the stable shared record and newer independent edits. It never deletes the entity, silently recreates it, restores an older approval or rewrites sealed/accepted history. Reaffirming or replacing an existing identity requires a later reviewed workflow, not repeating old creation receipts.

Source-to-created-origin dependency edges join existing conservative recursive transport propagation, including historical origins after authority loss. Parent/source structural changes make old origin reads stale. Withdrawal/hidden/superseded status and changed evidence assignments remove authority and invalidate dependent fields/heads/tasks; support changes preserve freshly reviewed identity links. New authoritative origin reads require their current head, exact projection, active unchanged proof and current accepted case. `v2_read_created_subject` returns reviewed_origin/stale/retired/unreviewed with no private actor/observation/rationale. Reviewed_origin describes initial materialization only: declared observation/effective dates are returned, not treated as current availability or timetable publication. It is not a confidence/expiry gate.

Supporting-evidence/account erasure clears proposal snapshots/fingerprints, origin snapshot, private copied edit/revision histories and current authority. Independently owned observations survive for fresh review; later transport snapshots may inherit an erased initial label and must redact. The anonymized shared transport draft can survive; account deletion remains the complete private intake erasure boundary. Reviewer/proposer-only deletion anonymizes actors/fingerprints while retaining independently owned evidence/origin. Standalone provenance erasure is not an API endpoint.
