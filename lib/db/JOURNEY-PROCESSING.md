# Correction and reported-journey processing

Additive0027 extends the existing intake/1 normaliser and bounded association facade; no public endpoint, automatic identity assignment or timetable is introduced. Existing migrations and worker lease/timeout/retry/commit fences remain immutable inputs to a guarded upgrade. Prior function body/security/search_path must match, allowing only CRLF representation differences.

Lead normalisation follows explicit same-author supersession chains from the original intake roots across contributions. It uses only active current leaves still assigned to that subject. Hidden/withdrawn/erased chains never fall back to an old value or copied birth snapshot; several active core answers remain unresolved. Original names and clock fields are unchanged. A private value-free correction marker prevents a replacement whose predecessor is erased from becoming an invented root. Previously erased unmarked legacy lineage cannot be reconstructed by this migration; inventory/review remains required before production backfill.

Actual reports use private reference-only input, evidence and cursor records. The original bounded intake facts and their current corrections supply evidence; follow-up independent reports are not silently treated as original intake. Header date/timezone/intention stays distinct from each fact's own service date/zone/offset/knowledge basis, and from scheduled time. Saving an actual report establishes no travel witness, default date, clock conversion, recurrence, fare or selected confidence. A missing/erased intake origin is unresolved rather than assigned invented attribution.

The actual-association/1 producer proposes same_service only to active runs under an explicitly selected run/service plan/pattern/route. Several runs stay several alternatives. Lead-only or missing intention remains unresolved; later source-reference and richer place/operator matching are still needed. A known different operator excludes the candidate. A name/alias is not a resolved operator. Actual clocks are not compared to scheduled clocks to identify a service or manufacture a correction. Reports are never moved or matched automatically.

Fifty-target pages, per-intention catalog epochs and durable wakeups cover large alternatives, new runs, parent edits and retirement. Original evidence revisions and structural context bind explained candidates. Unchanged rejected inputs do not reopen; genuine context/evidence changes can generate a new proposal. Existing candidate-bound reviewer roles and exact evidence requirements apply. A generated-link guard rechecks the complete current journey/run context. Acceptance/reversal preserves observations and does not itself rewrite matched_run_subject_id or publish a timetable. Usable authenticated review and retargeting remain separate API/UI work.

Five private tables have RLS/backend SELECT only; all new helpers remain owner-only. Existing fenced normalise/associate facades are the only mutation access retained for the backend. The existing minute Cron jobs can run the new stage after explicit preview application/activation; none is created by0027. Health includes actual-association/1 separately. Unsupported stages stay pending. A one-time scoped activation must queue surviving pre-existing actual reports and valid correction-led inputs; don't reset arbitrary leases or retry old unknown results.

Source/target generation, evidence withdrawal/erasure and contribution/account deletion invalidate copied inputs/digests and stale candidates. The correction marker contains only an existing observation ID and cascades when that observation is erased. Multi-stage recovery/backup restore and real-device/pilot acceptance remain required. Full cross-subject correction_of intake, source-ID/import integration, richer actual matching, authenticated forms/review, evidence/tasks/publication and complete R01–R14 remain open.
