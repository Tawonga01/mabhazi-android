# Actual journey intake capability

`POST /api/v2/actual-journeys` accepts schema1.0, clientSubmissionId, entrySurface, target.newActualJourney and1–20 typed observations. This separate path leaves the minimum new-lead and v1 contracts intact. The shared authenticated `/api/v2/receipts/:clientSubmissionId` recovers its historical save receipt too. Any public account with current Terms may contribute without reputation or email.

The API binds req.user.id, current Terms and expected-account header; JSON-only/uncompressed raw64KiB/origin protection applies. The database facade takes account-before-transport locks and verifies live account/Terms. Only the narrow facade is executable by the restricted backend role. The constructor/private helpers and hosted clients remain denied. A response is returned only after COMMIT; ambiguous failure requires receipt lookup before exact replay. Serialization retries use unchanged input/key and are bounded at three.

Supported facts: departure.actual and arrival.actual `{time:HH:mm}` with their own optional serviceDate/timezone OR offset; operator.reported `{name}`; cityId/named pickup/dropoff; paid/quoted/advertised fares with decimal string, supported ISO currency and directed city-pair/passenger/ticket scope. Optional fact/context knowledge and dates remain explicit, sources are already-owned UUID citations only. Clock fields never accept scheduled seconds or recurring calendars. Header trip date/zone never fills fact scope. Missing dates, price, knowledge or intention stays unknown; a report is not proof of travel, matched service or publication.

The generated OpenAPI client/Zod validates value shapes; server-owned checks reject unknown keys before Orval stripping, fractional IDs/revisions, duplicate citations, conflicting timezone/offset and missing conditional fare labels/date. SQL independently enforces registered types, dates, references, currency precision, ownership and atomic rollback. Decimal scale is canonicalised in the facade only after original currency precision validates; zero remains an explicitly submitted fare. Equivalent decimal-scale retries do not duplicate contributions.

There is no public canonical service/stop/operator catalogue yet. To avoid exposing or selecting hidden identities, this capability accepts no intended subject or an exact active community lead originally owned by the current account. It refuses private canonical/stop/operator IDs. Foreign and missing intended leads receive the same safe404. Stale own revisions return409; a new selection needs confirmation/new submission ID. Identical historical receipt replay still works after retirement; it does not restore facts or matching. This temporary visibility restriction is not a rule that public contribution must remain owner-only: independent reports are open to all accounts, and safe published target discovery must expand selection later.

`actualJourneyEnabled` is separate from minimumLeadEnabled and false unless the existing intake flag and exact installed facade privilege are ready. New code can deploy against0027 with actual intake disabled. Apply additive0028 only after exact-source CI and scoped permissions approval, then verify ledger/ACL and independent workers; preserve all0000–0027 bytes and existing credentials/signing. No new tables, role, paid service or runner is required.

This API stage has no new mobile actual-report form or installed APK. Existing minimum UI/receipt recovery remains compatible. Full typed/source-descriptor/import intake, public canonical selection, richer context matching, cross-subject corrections, authenticated reviewer/reversal screens, downstream assessment/tasks/publication, backup/restore, device/multi-user/legacy/pilot/release remain required.
